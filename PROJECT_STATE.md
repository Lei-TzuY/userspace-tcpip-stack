## Architecture

```text
                       ┌───────────────┐
   capture file  ───►  │  src/pcap.c   │  pcap + pcapng, both byte orders,
                       └───────┬───────┘  simple packet blocks
                               │  frame bytes + link type + timestamp
                       ┌───────▼─────────────────────────────────────┐
   src/main.c ────────►│      src/dispatch.c   stack_dispatch_link   │
   (CLI + read loop)   └───────┬─────────────────────────────────────┘
                               │
      ┌────────────────────────┼─────────────────────────┐
      │                        │                         │
  link layer               EtherType                  tunnels
  linktype.c               ethernet.c                 gre.c pppoe.c vxlan.c
  NULL/RAW/SLL/SLL2        VLAN                       IPIP / 6in4
      │                        │                         │
      └────────────► ipv4.c / ipv6.c ◄───────────────────┘  ← recursion,
                          │                                   depth-capped
          ┌───────────┬───┴──────────┬─────────┬─────────┐
       icmp.c      tcp.c          udp.c     igmp.c    sctp.c
       icmpv6.c       │              │
                      │              └── dns.c dhcp.c dhcpv6.c ntp.c quic.c
                      │
             tcp_state.c ──► tcp_analysis.c ──► report.c
             tcp_stream.c                        (JSON / CSV)
```

Cross-packet state lives in one `StackContext` (`src/dispatch.h`): the ARP
cache, the TCP tracker, the UDP tracker, and the two reassemblers. It is
heap-allocated because the TCP tracker alone holds a reassembly window per
endpoint.

Roughly 8,800 lines of C in `src/`, 2,900 of headers, 4,200 of tests, 3,700 of
Python generators, 900 of fuzz harness.

### Layering rules that hold today

- `main.c` knows about the command line and the read loop. Nothing else.
- `dispatch.c` is the only file that knows the shape of the protocol walk.
- `tcp_analysis.c` includes `tcp.h` and nothing else from the stack — the
  dependency is one-way, so the analysis can be unit-tested without a capture.
- `report.c` reads the trackers; nothing reads `report.c`.

### Round 2 — TCP expert analysis (`ae3f9b2`)

`src/tcp_analysis.{c,h}` turns a segment's position in sequence space into a
verdict: retransmission attributed to a cause (spurious / fast / RTO),
reordering told apart from loss, duplicate-ACK runs, window-full, zero-window
and zero-window probes, keep-alives, SACK-inferred holes, window scaling
applied per RFC 7323, and SRTT/RTTVAR/RTO estimation per RFC 6298.

`src/report.{c,h}` exports the conversation table as JSON or CSV, one record
per *direction* — a retransmission count for a whole "connection" would hide
which side retransmitted.

CLI grew `--quiet`, `--no-summary`, `--json[=PATH]`, `--csv[=PATH]`, `-h`.

`tests/sample-analysis.pcap` carries one connection per scenario, with
timestamps placed deliberately on each side of the analysis thresholds.

### Round 3 — encapsulation breadth (`cf5a9b2`)

- **Link layers**: Linux cooked v1 (113) and v2 (276), raw IP (101), BSD
  loopback (0). These captures previously printed `[skip]` and parsed nothing.
- **Tunnels**: IPv4-in-IPv4 (4), 6in4 (41) and the IPv6 equivalents, PPPoE
  discovery and session, VXLAN — joining the pre-existing GRE.
- **`STACK_MAX_ENCAP_DEPTH`**, the fix for the third bug below.
- Link type carried as `uint32_t` end to end; the pcap global header stores it
  in 32 bits, and narrowing to `uint16_t` would truncate a large declared value
  into a supported one.

### Round 4 — DNS depth, and the test suite's own assertions

- **EDNS0 (RFC 6891).** The OPT pseudo-record is lifted into `DnsMessage.edns`
  rather than listed as a resource record. Options decoded: Client Subnet,
  Cookie, Extended DNS Error, TCP Keepalive, NSID, Padding. Five distinct
  malformations are reported by name rather than dropping the message.
- **The 12-bit extended RCODE.** `dns_full_rcode()` composes the header's low
  four bits with the OPT's upper eight. BADVERS and BADCOOKIE cannot be
  expressed any other way, and reading the header alone reports them as
  NOERROR and YXRRSET — different answers, not truncated ones.
- **DNSSEC**, reported and never validated: DS, DNSKEY (with the key tag
  computed per RFC 4034 Appendix B), RRSIG, NSEC, NSEC3, NSEC3PARAM, plus the
  NSEC/NSEC3 type bit maps and the AD/CD header flags.
- **`tests/gen_dns_pcap.py` → `tests/sample-dns.pcap`**, one scenario per
  packet, and 32 new fuzz-corpus inputs.
- **Two defects in the test suite itself** — see bug 4 below.

### Round 5 — transport breadth: SCTP and QUIC

- **SCTP (RFC 9260).** Common header, the chunk walk, and the parameter and
  error-cause walks nested inside INIT / ABORT / ERROR. DATA, INIT, INIT ACK,
  SACK (gap blocks resolved to absolute TSNs), SHUTDOWN, ABORT, ERROR and
  FORWARD TSN are decoded; the rest are named, and an unrecognised type is
  reported with what RFC 9260 §3.2's top two bits say a receiver should do.
  Dispatched from both the IPv4 and the IPv6 switch.
- **CRC-32C**, the first checksum here that is not a one's-complement sum. A
  64-byte reflected nibble table, verified in the unit test against the
  published `123456789` check value and RFC 3720 Appendix B's all-zero vector
  rather than against itself. The capture carries one packet with a wrong
  checksum, so the verdict is exercised in both directions.
- **QUIC long headers (RFC 8999 / 9000 / 9369).** Version, connection IDs,
  token and Length; Initial, 0-RTT, Handshake, Retry and Version Negotiation;
  coalesced packets walked through the Length field with a cap; the RFC 9000
  §16 variable-length integer. Nothing is decrypted, and the packet number is
  not printed, because header protection masks even its length.
- **`tests/gen_transport_pcap.py` → `tests/sample-transport.pcap`**, 12
  packets, and 84 new fuzz-corpus inputs.
- **`#ifndef` guards on the `IPPROTO_*` defines in `dispatch.c`.** glibc
  declares these as enumerators and then defines each name as a macro
  expanding to itself, so the existing unguarded `#define IPPROTO_GRE 47` was
  a macro redefinition with a different token sequence — a diagnostic on GCC
  and Clang. It has never been seen because the CI jobs that would print it
  have never run.

## Bugs found and fixed

Four real defects, each found a different way and each *proven* rather than
asserted.

### 1. IPv6 Routing Header out-of-bounds read — found by fuzzing

`src/ipv6.c` copied Routing Header addresses before validating the declared
extension-header length. A Routing Header declaring `hdr_ext_len = 0x3a` copies
addresses from ~400 bytes past the end of the packet. The fix computes the
claimed length, validates it against the remaining bytes, and only then reads
anything it points at.

Proven by reverting to the pre-fix tree (`git stash`), confirming ASan fires on
the corpus, restoring, and confirming it passes.

### 2. `TcpOption.data_len` disagreed with what was stored — found by reading

`src/tcp.c` clamped the `memcpy` into the fixed option buffer but stored the
*declared* length in `data_len`. Any consumer walking the field would read past
the stored bytes. The fuzzer could not find this: no current consumer walks the
field, so nothing dereferenced the lie. Fixed by storing the copied length and
documenting the field as "length actually stored, not what the sender claimed".

### 3. Unbounded tunnel recursion → stack exhaustion — found by reasoning

`handle_ipv4 → handle_gre → handle_ipv4` is a recursion cycle with no counter;
the packet decides how many frames it consumes. A constructed capture nesting
GRE-in-IPv4 2,500 deep — 60 KB, inside the 64 KB read buffer — killed the plain
build with `0xC00000FD` `STATUS_STACK_OVERFLOW`. Depth 1,800 survived; the ASan
build died from 1,400.

Fuzzing could not find it: every nesting layer needs a valid IPv4 header
checksum, and random mutation will not produce one, let alone thousands in a
row.

After the fix, 2,720 layers (65,322 bytes, the deepest that fits the buffer)
exits 0, as does 3,200-deep IPIP entering through the raw-IP and loopback link
types.

### 4. The test suite's assertions did not always assert — found by breaking something on purpose

While checking that a new invariant test actually bit, a deliberately broken
`dns.c` produced a *600-second hang* instead of a failure. Two separate causes,
both in how the suite is built rather than in what it checks:

- **MSVC's debug CRT answers a failed `assert()` with a modal dialog box.**
  CTest waited for a click that would never come. The test did detect the
  regression; it just could not say so. `tests/test_support.c` now routes CRT
  assertion and error reports to stderr from a pre-main initialiser, and the
  same injected regression fails in 0.45 s with the file and line in the log.
- **`-DNDEBUG` is in CMake's Release flags, and the C standard defines `assert`
  as `((void)0)` when it is set.** Four of the seven CI jobs — Linux/Release,
  Windows/MSVC, macOS, and the big-endian s390x job — build Release, so their
  unit-test binaries were checking only that the process exited 0. Every
  `assert()` in `tests/` was a no-op in exactly the configurations that cover
  the other architectures. The `TEST_TARGETS` loop now applies `-UNDEBUG` to
  test targets only; the CLI and fuzz targets keep `NDEBUG` and their
  optimisations.

Verified by injecting the same regression into a Release build and confirming
it now fails (it would previously have passed), and by checking the generated
build files: `-UNDEBUG` lands after `/DNDEBUG` on test targets and nowhere else.

A blanket `TIMEOUT 300` on every CTest test was added at the same time. The
suite finishes in seconds natively, so anything still running after five
minutes has stopped making progress; CTest's own default is 1500 s, long enough
that a hang reads as a stuck CI job rather than a failed test.

### A harness bug that mattered as much

An early sanity check — deliberately injecting `data[len]` into `eth_parse` —
did **not** fail under `fuzz_pcap`. The replay driver was `malloc`ing 1 MiB
regardless of input size, and `fuzz_pcap` dispatched out of a 64 KB static
buffer, so every overread landed inside a valid object and ASan saw nothing.
Both now allocate exactly the input size, which puts a redzone immediately after
the last valid byte. **Bug 1 was only findable after this was fixed.**

Also fixed: `core.autocrlf=true` with no `.gitattributes` rewrote the LFs in
pure-ASCII corpus inputs, silently turning the `http_bare_lf` case into a
different test. Verified at the time (357 corpus files, 5 fixtures) that a fresh
checkout produced byte-identical files, and that `http_bare_lf` still contained
`0a` with no `0d`.

## Design decisions worth not relitigating

| Decision | Why |
| --- | --- |
| The protocol walk lives in `dispatch.c`, not `main.c` | The CLI, tests, and three fuzz targets exercise one implementation. Fuzzing a copy of the dispatch logic proves nothing about the CLI. |
| Encapsulation depth is a parameter, not a `StackContext` field | Context state persists across packets; a leaked depth would make one packet's nesting affect the next. |
| Tunnels and the depth cap shipped in one commit | VXLAN carries a complete inner Ethernet frame, so it returns the walk to the link layer and can nest without ever repeating an IP header. Adding it without the cap would have made the problem materially worse. |
| Retransmission verdicts ordered spurious → fast → RTO | Spurious is confirmed by the peer, fast has a protocol-defined trigger, RTO is a timing guess. Most-certain first. |
| Unknown window scale is `null`, not `0` | `0` is a real value meaning "no scaling requested". Reporting it for an unseen SYN would be a fabricated observation. |
| One CSV/JSON record per direction, not per connection | Every quantity the analysis produces is directional. |
| `--json`/`--csv` to stdout implies quiet | A structured document interleaved with the packet walk parses as neither. |
| Fuzz corpus is checked in | A crash found once becomes a permanent regression test by dropping the file in a directory. |
| The OPT record is hoisted out of the additional section | Its class field is a UDP payload size and its TTL field is a flags word. Printing it as a record about a name states three falsehoods in one line. |
| DNSSEC is reported, never validated | Validation needs a trust anchor, a clock, and a crypto implementation. Reporting the key tag is what makes the records readable as a chain, and it is arithmetic rather than cryptography. |
| RRSIG timestamps are converted without `gmtime()` | The wire field is 32 bits unsigned and `time_t` is signed and often 32 bits, so half the range comes back negative or NULL. |
| Test targets are built with `-UNDEBUG` | Otherwise Release compiles every assertion in the suite away, which is what four of the seven CI jobs build. |
| Both a libFuzzer build and a portable replay driver | libFuzzer needs Clang, which is not available on the development machine. The replay driver runs the corpus under CTest with any compiler, and has a dumb mutation mode that still found real bugs under ASan. |
| Heuristic thresholds are labelled as heuristics in the code | A capture taken at the other end of the path can legitimately disagree with a timing-based verdict. |
| QUIC needs a port match as well as a structural sniff | An ordinary iterative DNS query whose ID ends in `0xff` reads byte for byte as a long header of an IETF draft version. Losing QUIC on an unusual port is a smaller error than taking one DNS query in a thousand away from the DNS parser. |
| QUIC's packet number is not printed | Header protection masks the two bits that say how long it is, so any value shown would be a guess dressed as an observation. |
| An unknown QUIC version stops the parse at the connection IDs | RFC 8999 defines nothing beyond them. Applying version 1's layout to a version that does not exist yet produces confident nonsense. |
| SCTP chunk detail is decoded at parse time, lists are capped | The unit tests can then assert on values rather than on printed text, and a packet cannot make the parser allocate. `value_len` is what arrived, never what was declared — the same rule as `TcpOption.data_len`. |

### Fuzz campaigns run

Hand-written mutation mode only (no Clang on this machine), under ASan:

```sh
./build-asan/fuzz_parsers_replay --mutate=100000 --seed=1 \
    --save-current=<scratch>/current.bin fuzz/corpus/parsers
```

Mutation is deterministic given `--seed`, so a crash reproduces: re-run with the
same seed and read `--save-current`. Round 3 ran three targets × two seeds
(21, 22), round 4 the same with seeds 31 and 32, and round 5 with 41 and 42 —
about 600,000 inputs per round, all clean.

## Known issues and unverified claims

Stated plainly because each one is a place where the project could be less
correct than it looks.

1. **The 7 CI jobs have never run.** The YAML is syntactically valid and the
   commands work locally, but no job has executed. The Windows job is the one
   most likely to pass (it matches local development); the s390x big-endian job
   and the libFuzzer smoke job are the most likely to need a fix. Note that
   until round 4, four of those jobs would have passed while checking far less
   than they appeared to — see bug 4 — so "CI is green" was never going to mean
   as much as it sounded.
2. **libFuzzer has never been executed.** There is no Clang on the development
   machine. Every finding so far came from the hand-written mutation driver,
   which has no coverage feedback and is far weaker. The first real
   coverage-guided campaign may well find something.
3. **UBSan has never run.** MSVC has no UBSan, so the `-fno-sanitize-recover=undefined`
   configuration has only ever been configured, never executed. Pre-existing
   undefined behaviour — most plausibly unaligned loads or signed overflow in
   the checksum paths — may surface on its first CI run.
4. **The branch is not pushed and no PR exists.** All four commits are local.
5. **Timing-based TCP verdicts are heuristics.** The RTO floor (200 ms) and the
   reordering window (3 ms) are choices, not protocol constants. Traffic on a
   very fast path can have genuine retransmissions inside the reordering window.
6. **`fuzz_pcap` is slow** because the reader opens by path, so every input is
   written to a temporary file. Give it its own process in a long campaign.
7. **No live capture.** Offline files only; there is no `pcap_open_live`
   equivalent and adding one would need libpcap, which the no-dependency rule
   currently forbids.
8. **SCTP and QUIC are parsed per packet, not tracked.** There is no
   association state for SCTP — no TSN accounting, no bundling across packets
   — and no QUIC connection table keyed by connection ID, so a migration or a
   retired ID is invisible. Both are the same shape of work `tcp_state.c` does
   for TCP, and neither was attempted in round 5.
9. **QUIC is only recognised on ports 443, 4433, 8443 and 853.** That is a
   deliberate trade (see the design table), but it does mean QUIC on any other
   port shows as plain UDP. A short-header packet on one of those ports is
   reported as 1-RTT on the strength of the port alone.
